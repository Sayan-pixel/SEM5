Fast Ethernet keeps every MAC rule and only shrinks the bit time from 100 ns to 10 ns; this part you need to compute that shrink and then build the 100Base-TX and 100Base-FX encoders that achieve it.

802.11 MAC header decoder
You need to decode six captured 802.11 headers, first by hand and then with a Python parser, and use the ToDS/FromDS bits to name every address.

Format reminders
Frame Control is 2 bytes. In the first byte, bits 0-1 are Protocol Version, bits 2-3 are Type (00 management, 01 control, 10 data) and bits 4-7 are Subtype. The second byte holds the flags, from bit 0 upward: ToDS, FromDS, More Frag, Retry, Power Mgmt, More Data, Protected, Order.
Duration/ID and Sequence Control are 16-bit little-endian fields. In Sequence Control, the low 4 bits are the fragment number and the high 12 bits are the sequence number.
Address 4, when present, comes after Sequence Control.
Control subtypes you need: 1011 = RTS, 1100 = CTS, 1101 = ACK. RTS carries two addresses; CTS and ACK carry only one.

2. Parser (7 marks)
Write Python code (parser.py), write decode_80211(hexstr) that returns a dictionary with type, subtype name, all flags, duration, every address labelled with its role (RA, TA, DA, SA or BSSID, following the ToDS/FromDS table on the slides), sequence and fragment numbers, and the EtherType from the LLC/SNAP header when the frame is data. Print a neat one-block summary for each of F1-F6.

Your code must pick the right address roles purely from the ToDS/FromDS bits, handle frames with one, two, three or four addresses, and report an error for input that is too short.

C3. Interpretation (3 marks)
1. F3, F4 and F5 are one exchange. Name the sender and receiver of each, and explain why the Duration drops from F3 to F4 to F5.
2. A station that hears only F4 sets its NAV. For how many microseconds, and which slide mechanism does this implement?
3. F2 has the Retry flag set. How does the receiver use the Retry bit together with the sequence number to discard duplicates?
4. Why does F6 need a fourth address? Sketch the path it takes, using the WDS figure from the slides.

Optional check: capture your own Wi-Fi traffic in monitor mode with Wireshark and compare one data frame against your parser's output.
